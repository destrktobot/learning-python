Comprehensions: The map/filter Remap

Python lists have no .map() or .filter(). What replaces them is better — once your eye learns to parse it.

The mental model

In JS you transform arrays by chaining methods. In Python you write a comprehension: a single expression that builds a new list. It reads in this order:

[ EXPRESSION  for ITEM in ITERABLE  if CONDITION ]
#   "map"          "for...of"          "filter"

The if filters first — only items that pass it reach the expression. So one comprehension replaces a whole .filter().map() chain:

JavaScript

const names = users
  .filter(u => u.active)
  .map(u => u.name);

Python

names = [u["name"]
         for u in users
         if u["active"]]

(One line is fine too: names = [u["name"] for u in users if u["active"]]. Note dict access is u["name"], not u.name — dicts aren't objects-with-dot-access. That distinction gets its own lesson.)

Dict comprehensions

Same idea, curly braces, with a key: value expression — the remap for Object.fromEntries(...map(...)):

JavaScript

const roleByName = Object.fromEntries(
  users.map(u => [u.name, u.role])
);

Python

role_by_name = {u["name"]: u["role"]
                for u in users}

Looping when you're not building a list

For side effects (printing, appending to several places), use a plain loop — there's no .forEach either. Two loop tools you'll want immediately:

for user in users:              # for...of
    print(user["name"])

for i, user in enumerate(users):  # when you need the index
    print(f"{i}: {user['name']}")

if "Ben" in names:              # .includes() → the `in` operator
    print("found")
Gotcha

When a comprehension needs nesting or a tricky condition, stop and write a plain loop. A comprehension you have to re-read is worse than three clear lines. Idiomatic Python treats unreadable one-liners as a smell, not a flex.

Hands on: predict, then run

You tested the falsy branch last time, so this exercise is prediction-first. In hello-python/main.py, add:

users = [
    {"name": "Ben", "role": "admin", "active": True},
    {"name": "Ada", "role": "user", "active": True},
    {"name": "Sam", "role": "admin", "active": False},
]

Now — before running anything — write down what each of these prints, then translate the JS and check yourself with uv run main.py:

  1. console.log(users.filter(u => u.active).map(u => u.name))
  2. console.log(Object.fromEntries(users.map(u => [u.name, u.role])))
  3. Harder: the names of users who are active admins, uppercased. (Strings have .upper().)

Expected: ['Ben', 'Ada'], then {'name': 'role'}-style dict with all three users, then ['BEN']. If a prediction missed, figure out why before moving on — that gap is the lesson.
