The comprehension shells

The surrounding brackets are the collection's literal syntax — the shell picks what you build:

roles        = {u.role for u in users}          # set   (unique values; no colons)
roles        = [u.role for u in users]          # list  (Python's word for array)
role_by_user = {u.name: u.role for u in users}  # dict  (the colon makes it one)
lazy_roles   = (u.role for u in users)          # generator — NOT a tuple (lazy, consume-once)

Access mode matches the data you iterate: dot for dataclasses (u.role), brackets for dicts (u["role"]). Empty {} is always a dict — an empty set is set().

Loops

Loop over items — for...of → for...in

JavaScript

for (const user of users) {
  console.log(user.name);
}

Python

for user in users:
    print(user.name)

Careful: Python's for...in is JS's for...of (values), not JS's for...in (keys). Same words, opposite meaning — iterating a Python dict directly gives keys, though (see below).

Need the index — enumerate

JavaScript

users.forEach((u, i) => {
  console.log(`${i}: ${u.name}`);
});

Python

for i, u in enumerate(users):
    print(f"{i}: {u.name}")

Counted loop — range

JavaScript

for (let i = 0; i < 5; i++) { ... }
for (let i = 10; i > 0; i -= 2) { ... }

Python

for i in range(5):        # 0,1,2,3,4 (end-exclusive)
for i in range(10, 0, -2) # 10,8,6,4,2 (start, stop, step)

There is no C-style for(;;) in Python. Looping over range(len(xs)) to index into xs is an anti-pattern — use enumerate.

Loop over a dict

JavaScript

for (const [k, v] of Object.entries(o)) { ... }
for (const k of Object.keys(o)) { ... }
for (const v of Object.values(o)) { ... }

Python

for k, v in d.items():    # entries
for k in d:               # keys (the default!)
for v in d.values():      # values

Two lists in lockstep — zip

names = ["Ben", "Ada"]
roles = ["admin", "user"]
for name, role in zip(names, roles):
    print(f"{name}: {role}")     # Ben: admin / Ada: user

while — and the missing do...while

JavaScript

while (queue.length > 0) { ... }

do {
  attempt();
} while (!ok);

Python

while queue:          # truthiness: empty list is falsy
    ...

while True:           # no do-while; this is the idiom
    attempt()
    if ok:
        break

break and continue work exactly as in JS. Curiosity you'll meet reading others' code: a for/while can have an else: clause that runs only if the loop finished without break — rarely written, worth recognizing.

Dicts, JSON & dataclasses

The four ways to read a dict key, at a glance:

d = {"name": "Ben"}
d["role"]                  # KeyError: 'role'  — loud, at the exact line
d.get("role")              # None              — your ?. equivalent
d.get("role", "user")      # "user"            — your ?? with a default
"role" in d                # False             — check before you leap

Boundary rule: dicts at the wire (JSON in/out), dataclasses inside your logic. Missing-key reads: brackets when the key must exist (let KeyError find bugs), .get() only when absence is legitimate.
