Glossary

Python's names for things, anchored to what a JS developer already knows. Terms are added as lessons introduce them — say the Python word out loud; vocabulary is half of fluency.

Collections

TermWhat it isJS anchor
listOrdered, mutable sequence: [1, 2, 3]. Never called an "array."Array
dictKey → value mapping: {"a": 1}. Keys keep their type; missing key raises KeyError (use .get()). Preserves insertion order.Map, not {}
setUnordered bag of unique values: {1, 2, 3}. No indexing. Empty one is set(), because {} is a dict.Set
tupleFixed, immutable sequence: (1, "a"). Parked for a later lesson.~frozen array
comprehensionA collection literal with a loop inside: [expr for x in xs if cond]. The shell ([], {k: v}, {v}) picks list/dict/set..filter().map() chain
generatorLazy, consume-once iterator; (expr for x in xs). Flagged, not yet taught.generator/iterator

Values & syntax

TermWhat it isJS anchor
NoneThe single absent value. Test with x is None.null (+undefined)
f-stringInterpolated string: f"Hi {name}". Same-quote nesting needs Python ≥3.12.template literal
truthy / falsySame idea as JS; additionally empty collections ([], {}, set()) are falsy.truthy/falsy
subscriptableSupports square brackets: x[...]. Lists and dicts are; dataclass instances and sets are not.bracket access
snake_case / PEP 8The naming convention and the style guide that mandates it.camelCase, but underscored
dataclassDeclared-field class via @dataclass; dot access, generated constructor/eq/repr. On-ramp to Pydantic.TS interface, at runtime
tracebackPython's stack trace. Read bottom-up: last line names the error.stack trace
type()Asks any value what it is: type(x). First tool when output surprises you.typeof, but honest
